# OMIC-16: internal capture in the existing Collector SQLite

Status: implementation plan for adversarial review. No OMIC-16 code or production migration has begun. This plan does not authorize changing the public ready format or the external ACK protocol.

## Goal and observable boundary

The Collector currently stores private attempt, quarantine, and draft audio in `records.bin` files while its control state is in `collector-state.sqlite3`. The operator approved moving **only internal work** into that existing SQLite. Public `ready/<bundle-id>/records.bin` and `manifest.json` stay ordinary immutable files retrievable by any consumer; their names, bytes, manifest schema, UTC behavior, and ACK checkpoint remain compatible. The stable zero-content `collector.lock` remains the sole singleton lock. No archive, fallback raw writer, second permanent database, optional backend, or new alarm for known small firmware losses is part of this change.

The 2026-10-13 live reference was 124 working files: 94 ready output files (47 pairs), 28 draft files (14 pairs), the SQLite file, and the lock. On that fixed snapshot, successful consolidation yields 96 files: the same 94 output files plus SQLite and lock. Actual live counts may change during capture; acceptance reconciles each category and verifies zero private attempt/draft/quarantine audio files, rather than treating 96 as a timeless absolute. Transient SQLite journal files and the single owned recoverable ready-output stage are classified separately.

## Existing contracts and implementation reach

The read path is `application/collector.py` → `domain/transfer_arena.py` → `adapters/attempt_writer.py` (one writer thread) → `adapters/staging_writer.py` → `adapters/attempts.py`. The writer drains up to 128 complete records per call; the configured durability cadence is 1,024 records, with explicit barriers. A ring record is exactly 444 bytes: the original four-byte **big-endian** device timestamp and 440 exact payload bytes. Notifications may split a record arbitrarily. `READ_BEGIN` must bind the prepared range before DATA. The current attempt raw/checkpoint path is in `attempts.py` and `staging_filesystem.py`; `staging_store.py` composes capture and publication. `opportunistic_runtime.py`, `application/ports.py`, `application/batch_reconciliation.py`, `application/session_lifecycle.py`, `cli.py`, and status/metrics callers consume those contracts.

`adapters/ready_bundles.py` authenticates draft and ready files, normalizes overlapping sources, groups physical continuity, requires a drained closure plus `ceil(target_audio_seconds * 50)` packets, converts timestamps through the existing clock segment mapper, writes/fsyncs/renames public output, then commits the ready ledger. It retires output only after exact external ACK `(bundle_id, records_sha256)` and open-speech-tail preflight. Preserve these semantics and the existing `ready_machine.py` decisions. Replace the draft-file input and UUID scratch only. `adapters/publication.py`, `quarantine.py`, `attempt_cleanup.py`, `staging_contract.py`, `staging_filesystem.py`, `staging_store.py`, `storage_layout.py`, `spool_metrics.py`, and operator-status/CLI views must be audited so no active private-file writer, reader, cleanup, or stale metric remains.

`collector_state_db.py` currently has schema version 1 and one generic JSON `state(kind,id,payload)` table, DELETE journal mode, `synchronous=EXTRA`, a 5-second busy timeout, and a per-call connection. Production's existing metadata, ready ledger, clock state, quality rows, and migration marker must survive an additive version-2 schema. `state_migration.py` currently migrates only control files, not raw audio. `scripts/deploy-systemd-service.sh` stops the service, runs staged `migrate-state`, switches the release, and has rollback/finalize traps; that rollback path is part of the change.

## Typed model and durability contract

Add typed tables to the **same** SQLite, while retaining the existing metadata table: `capture_source` (identity, source type, lifecycle, unsigned sequence start and limit, prepared/read-begin range, committed count/SHA, closure/block reason, quarantine terminal state/reason/time and retention deadline), `capture_record` (source identity + ordinal primary key, queryable original `device_timestamp` INTEGER constrained to uint32, exact 440-byte payload BLOB, nullable queryable derived `utc_timestamp` INTEGER, and mapping revision), `capture_tail` (**at most one row per source**, with leg/high-water identity, exact byte offset and 1–443 bytes), `capture_conflict` (exact rejected bytes split into bounded chunks of at most one 128-record drain, offset/source/leg and reason, never overwriting accepted evidence), `capture_evidence` (typed legacy opaque/quarantine entry kind, owned path, inode identity, terminal state/reason/time and bounded byte chunks or symlink link text without following the link), `publication_cohort` (durable accepted permit, closure frontier, threshold/config observed, ordered source/slice membership and progress), and `ready_output_stage` (one deterministic owned active output intent, expected bundle identity/digest/ranges, progress and ownership). Names can change in code, but each field and invariant must have a typed, checked representation; opaque JSON audio blobs or a second DB are unacceptable. `CHECK` constraints enforce uint32 device and UTC timestamp ranges, 440-byte payload, tail bound, and nonnegative ordinal. Store uint64 sequence values losslessly as fixed-width eight-byte big-endian BLOBs (or an equivalently proved encoding), with explicit Python boundary validation and lexicographic ordering; never narrow them through SQLite signed INTEGER. Ordinal/count fits the protocol's uint32 bound. Reconstruct exact original bytes as `device_timestamp.to_bytes(4, "big") + payload` and compare streaming SHA-256 and count to the source checkpoint. Refresh derived UTC for unpublished rows from the existing clock mapper when its revision changes and again before freezing an output-stage mapping; `NULL` with a current revision denotes an unknown/unrepresentable UTC mapping. This is a queryable projection, not a second source of original truth or a global clock/provenance snapshot. Original device timestamps and payloads never change, and already published ready remains immutable.

The writer thread remains the only capture SQL writer. Every delivered drain of **up to 128 complete records, including a shorter drain**, is one short committed transaction: rows, count/SHA checkpoint, and the current exact tail are atomic. It closes the transaction before the thread returns to its idle wait; no transaction stays open while BLE is idle or any other StateDB writer runs. The old 1,024-record setting was a raw-file fsync/checkpoint cadence, not the recoverable-byte boundary; remove `durability.checkpoint_records` from the new active config/schema/templates/docs/callers instead of retaining a periodic verification fiction. The explicit `checkpoint()` API still drains its captured high-water and tail and returns the committed prefix. Legacy import reads old recorded checkpoint metadata without requiring that knob at runtime. This matches the old raw writer's process-kill survival of each delivered aligned chunk; the former raw file wrote each drain immediately and promoted its aligned tail on restart even before its 1,024-record fsync/checkpoint. A power-loss guarantee is separately measured, not inferred from process-kill behavior. If measured per-drain SQLite commits cannot keep up with the largest real batch, revise and re-review the durability design before relaxing it; do not silently widen confirmed-loss exposure.

Synchronously **before any await** at command admission on the event-loop thread, copy immutable `(source_id, leg_generation, complete-record high-water, absolute received high-water, exact tail offset, tail bytes)` from the loop-owned `TransferArena`; the writer must never read a mutable live tail. The arena's existing replay comparison leaves bytes below the captured received watermark immutable. The writer drains only the captured complete high-water and commits only the copied snapshot with its rows/checkpoint, acknowledging the frontier after COMMIT. On a recovery leg, a shorter incoming replay compares against only the incoming prefix and **retains** the longer saved tail; equal replay may extend it, and a mismatch stores the exact rejected bytes in typed conflict evidence and blocks without overwriting accepted bytes. One tail row is atomically replaced with the source frontier, never accumulated per leg. A committed tail never advances the complete-record sequence frontier. `PREPARE_LEG` is its own durable event: it bounds the new leg within the immutable source snapshot, permits replay start no later than the durable next sequence, increments `leg_generation`, and stores its start/count before issuing READ. If called while receiving, it first commits the current barrier/interruption in the same short transaction. A matching-generation `READ_BEGIN` then re-enters receiving; DATA before it is refused. An exact duplicate READ_BEGIN for the current generation is idempotent only where the current adapter already permits it.

If `COMMIT` reports an ambiguous failure, close and reopen the authoritative DB and compare the proposed count, SHA, tail, and rows before acknowledging it. If the comparison cannot establish exact commit or rollback, fail stop. SQLite busy contention gets bounded retry/backoff on the writer thread with a finite measured deadline; ordinary concurrent clock/quality writes and read-only status must complete without exhausting it, while an overlong reader or damaged DB fails deterministically and prevents `ADVANCE`. Disk-full, corruption, or any unresolved DB failure prevents seal success and pendant `ADVANCE`; do not silently create an empty replacement DB or write fallback raw. A validated full seal must be committed before the existing `ADVANCE` command is sent. The existing single-process guard covers every mutating/BLE command; read-only status may inspect the database without taking the flock.

## Total lifecycle decisions

The implementation must encode and test this total transition matrix. `REFUSE` means deterministic no-mutation rejection; an unexpected data conflict instead uses `BLOCK` and retains exact evidence. `INTERRUPTED` means a recoverable interrupted transfer, while `SEALED_WAITING` means a complete validated DONE source or durably terminalized prefix awaiting publication; these names avoid confusing transport recovery with product-level pending audio. `RETIRE` is allowed only when every unique physical record has authenticated durable ready custody/lineage (or an explicit zero-record terminal source). After public files are durable, commit ledger/coverage proof and a typed `RETIRING` cursor; delete covered rows in bounded transactions and resume from that cursor after a crash. Retaining source bytes until downstream external ACK is unnecessary: ACK governs **public ready output** retirement, not private source custody. A blocked source may retain certified salvage-prefix rows awaiting ready custody and separate residual evidence awaiting its retention deadline.

| Current state | create source | PREPARE_LEG | matching READ_BEGIN | matching record/replay | barrier | validated DONE / terminal prefix | interruption | conflict | full ready custody |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| absent | prepared | REFUSE | REFUSE | REFUSE | REFUSE | REFUSE | REFUSE | REFUSE | REFUSE |
| prepared | REFUSE | leg_prepared | REFUSE | REFUSE | prepared (durable zero prefix) | REFUSE | interrupted | blocked | REFUSE |
| leg_prepared | REFUSE | exact identity idempotent, else REFUSE | receiving | REFUSE | leg_prepared | REFUSE | interrupted | blocked | REFUSE |
| receiving | REFUSE | leg_prepared after atomic barrier and bounded leg check | REFUSE except permitted same-generation retry | receiving | receiving (commit) | sealed_waiting (commit) | interrupted (commit) | blocked | REFUSE |
| interrupted | REFUSE | leg_prepared after bounded leg check | REFUSE | REFUSE | interrupted | sealed_waiting only with authenticated prefix | interrupted | blocked | REFUSE |
| sealed_waiting | REFUSE | REFUSE | REFUSE | REFUSE | sealed_waiting | sealed_waiting (idempotent identity) | sealed_waiting | blocked only on newly authenticated conflict | RETIRE when all unique coverage is ready |
| blocked | REFUSE | REFUSE | REFUSE | REFUSE | blocked (inspect only) | REFUSE | blocked | blocked | REFUSE; certified salvage prefix uses the separate quarantine disposition FSM |

The separate retirement sub-FSM is `COVERED` (durable ready files + ledger/lineage) → `RETIRING(cursor)` → absent. Only a bounded, idempotent delete step may advance a `RETIRING` cursor; capture, replay, cohort admission, and ACK events refuse in that state. Each chunk deletes at most the measured safe row quantum, and the final chunk removes the source metadata after confirming the stored coverage proof. A crash at any cursor resumes from the authoritative SQL rows. The quarantine disposition FSM below owns residual evidence independently from certified audio coverage.

The publication-cohort FSM has these exhaustive state/event decisions: `UNQUALIFIED` + no drained threshold → wait; `UNQUALIFIED` + drained qualified threshold → atomically `ACCEPTED` with ordered source/slice membership and observed threshold before the first output; `ACCEPTED` + next group → `STAGING`; `STAGING` + owned incomplete output → reconcile/rebuild the same group; `STAGING` + durable destination → ledger commit and advance the cohort cursor to `ACCEPTED` or `COMPLETE`; `COMPLETE` + all unique coverage proved → retire cohort and covered source rows; other event/state pairs refuse without mutation. A 2,000-second group followed by a 1,600-second group under a 3,600-second threshold must finish after a crash following the first output, because the persisted permit applies to the whole accepted cohort; do not reapply the threshold to the remainder. New sources arriving after permit creation are a later cohort, not silently added to the frozen membership. Existing clock observations can refresh only **unpublished** groups; once a group gets a stage intent, its range mapping is frozen for deterministic retry. Subthreshold input without a drained qualification waits indefinitely as today. Preserve closure frontier, overlap/gap normalization, complete payload equality, no double publication, and immutable output/ACK behavior. Bump `publication_generation` in the same SQL transaction as each publishable source closure, clock/closure change, cohort/stage transition, or source retirement; `_publication_revision` combines that generation with existing ready-file and downstream ACK-checkpoint identities, so the reducer wakes after a restart or changed SQL input.

The original `capture_record.utc_timestamp` is a query-only projection. Public output must still derive `time_ranges` from `ClockSegmentMap` and apply `_clear_unrepresentable_ranges` to an **entire range** when any record would overflow uint32; in that case all records in that range retain original device timestamps and the manifest has `utc: null`. Never write ready bytes by independently substituting each row's projected UTC value. Keep the existing `floor(timestamp + offset + 0.5)` rule and compare output byte-for-byte to the current overflow and boundary fixtures.

Quarantine has a separate typed disposition/retention FSM: unclassified evidence becomes `PUBLISHED_PREFIX` only after a certified checkpoint count/SHA and successful salvage eligibility, or `UNPROCESSABLE` after a typed reason; reclassification conflicts refuse. `PUBLISHED_PREFIX` means **internal draft-eligible custody**, not public ready custody. Its certified prefix points to the **same source rows**, with no copy; it remains eligible indefinitely below the ready threshold. A 72-hour retention sweep may remove terminal residual tail/conflict/opaque evidence only when no pending/cohort/ready-custody decision needs it; it cannot remove the certified prefix audio before full durable ready coverage. Both dispositions with insufficient age or live references keep evidence; expired unreferenced terminal evidence retires in a bounded SQL transaction. A nonterminal/unknown state refuses automatic deletion. This replaces old file-first `deletion_pending` and attempt cleanup intents with SQL-atomic row deletion; post-crash retry reads the authoritative row state. The `cleanup-attempts` CLI is removed or given a clearly typed SQL maintenance meaning, never a hidden file sweep. Test every state × age/reference condition and prefix salvage/restart semantics.

## Ready-output crash protocol

Before writing a public group, persist a stage intent keyed deterministically by its accepted cohort and bundle identity, including its frozen source slice geometry and time ranges for that output. Use one owned hidden staging directory/pair for the active group; the concrete current hard-kill risk is `ready_bundles._write_ready_group`'s hidden UUID directory, which `recover_capture_temporaries` does **not** reconcile because that function only covers capture-root staging. Stream original DB rows in bounded chunks, apply the existing UTC conversion, write `records.bin`, fsync it, write the unchanged canonical manifest, fsync the directory, rename to the final ready name, then fsync the ready parent. Only after this durable boundary commit the existing ready ledger identity/lineage, cohort cursor, coverage proof and `RETIRING` intent; then delete covered private rows in bounded restart-resumable transactions. Startup/retry first reconciles the deterministic stage and any already durable destination against the SQL intent, output hashes, manifest, and ledger. It may resume or rebuild only an **owned authenticated** incomplete stage; an unknown or unowned file/dir is preserved and causes a clear block. The output stage is removed after a finished group; there is never unbounded hidden scratch accumulation. Existing ready files are never rewritten, and ACK retirement remains ledger-first and exact-identity guarded. The bounded, old capture-root temporary recovery remains a distinct legacy-migration input; do not claim it covers ready-root scratch.
