The draft growth issue is real even though today's 16 pairs are justified. After 59 one-minute confirmed drafts, the design can hold 118 draft files while still below the 60-minute packaging gate; with one-second fragments, thousands of files are possible for the same audio duration. There is no finite file-count bound from the 60-minute threshold because positive fragments can be arbitrarily short, and subthreshold audio may wait indefinitely by contract. A single append accumulator with committed offsets in the existing SQLite database would bound file count, but it must represent discontinuous sequence ranges and exact overlaps, replay an interrupted append, and reclaim an already published prefix while newer audio remains. The panel therefore rejects treating it as a trivial two-file deletion. The architectural recommendation is to design a bounded pending-audio representation after the verified duplicate cleanup, with an explicit crash and byte-parity comparison against the current pair design; implement it only if that design is simpler end to end. No arbitrary age flush, archive, or numeric file target is justified by this audit.
