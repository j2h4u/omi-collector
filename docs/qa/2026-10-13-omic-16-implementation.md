# OMIC-16 implementation and acceptance receipt

The [accepted implementation plan](../OMIC-16-IMPLEMENTATION-PLAN.md) is a frozen design artifact (SHA-256 `a2cd82eba1d2faa8a16679ae5fdcfb3f91179f8f3a29133036e199ea6de64793`). Its [planning review](2026-10-13-omic-16-plan-review.md) reports design agreement, not implementation or deployment. This receipt tracks the resulting code and separate release evidence. At this stage, the implementation is in a candidate checkout; no production cutover or hardware capture has been verified.

The implementation stores private capture records, tails, checkpoints, source lifecycle, recovery and quarantine evidence, and publication custody in the existing Collector SQLite database. The single stable `collector.lock` protects mutating runtime and the stopped-service migration. Public `ready/` bundles remain external immutable `records.bin` and `manifest.json` files; downstream publication is outside OMIC-16 scope.

The one-way migrator imports supported v1 private audio and state into a verified v2 candidate, then deletes only inventoried old private copies. It refuses unsupported terminal-retired attempts, orphaned metadata, attributable v1 quarantine, spool-rooted v1 quarantine, and unknown private artifacts before writing a cutover receipt or changing the old tree. The spool-rooted refusal closes a cleanup accounting gap for an uncommitted quarantine move; opaque quarantine in inventoried roots remains supported. The live pre-cutover inventory reported zero v1 attempt and quarantine rows and no physical attempt entries, so those refusal cases are a fail-stop boundary rather than an accepted migration loss. A durable new-release selector is not rolled back to an old runtime after v2 activation or an ambiguous cutover. The finite OMIC-17 followup removes one-time v1 import and receipt code after live OMIC-16 acceptance; it is not a permanent compatibility layer.

Initial adversarial review of the mutable checkout found startup and retirement risks that are now corrected and covered by focused tests: a SQL-owned ready stage left by SIGKILL is accepted for deterministic publication retry while foreign scratch remains blocked; routine runtime/status opens no longer scan the full audio database; stopped migration strictly validates the typed schema on candidate activation and v2 reentry; and publication follow-up stops when no ready boundary or retirement progress exists. Cursor-ahead restart, pre-READ space admission, bounded journal reserve, capped UTC projection refresh, and its idle-maintenance hook passed focused checks. The obsolete checkpoint-count setting was removed. Residual quarantine evidence expires independently because publication reads canonical capture records; source retirement remains pinned while publication custody references it. These are initial findings, not a final release verdict.
