# OMIC-16 implementation and acceptance receipt

The [accepted implementation plan](../OMIC-16-IMPLEMENTATION-PLAN.md) is a frozen design artifact (SHA-256 `a2cd82eba1d2faa8a16679ae5fdcfb3f91179f8f3a29133036e199ea6de64793`). Its [planning review](2026-10-13-omic-16-plan-review.md) reports design agreement, not implementation or deployment. This receipt tracks the resulting code and separate release evidence. The current unreleased candidate `38904dda48104fb303a269332128869cdc941437` passed all five project gates, including the active-READ disk-failure correction and both independent premium SOURCE GO reviews. Its migration and SQLite storage components are unchanged from `8737267a52a0439a9f48111511263026b113a814`, which passed both exact-image capacity replays and all three actual root-principal migration cases. The operator removed the old-release throughput baseline from acceptance; real-pendant behavior is to be checked after installing the corrected release. The prior release remains selected, but its service is intentionally stopped awaiting that cutover. The first historical capacity-run timeout remains unexplained.

The implementation stores private capture records, tails, checkpoints, source lifecycle, recovery and quarantine evidence, and publication custody in the existing Collector SQLite database. The single stable `collector.lock` protects mutating runtime and the stopped-service migration. Public `ready/` bundles remain external immutable `records.bin` and `manifest.json` files; downstream publication is outside OMIC-16 scope.

The one-way migrator imports supported v1 private audio and state into a verified v2 candidate, then deletes only inventoried old private copies. It refuses unsupported terminal-retired attempts, orphaned metadata, attributable v1 quarantine, spool-rooted v1 quarantine, and unknown private artifacts before writing a cutover receipt or changing the old tree. The spool-rooted refusal closes a cleanup accounting gap for an uncommitted quarantine move; opaque quarantine in inventoried roots remains supported. The live pre-cutover inventory reported zero v1 attempt and quarantine rows and no physical attempt entries, so those refusal cases are a fail-stop boundary rather than an accepted migration loss. A durable new-release selector is not rolled back to an old runtime after v2 activation or an ambiguous cutover. The finite OMIC-17 followup removes one-time v1 import and receipt code after live OMIC-16 acceptance; it is not a permanent compatibility layer.

The final active-READ correction gives the one writer-failure latch a thread-safe wakeup for a quiet BLE READ. The collector races that signal with each notification, prioritizes an already latched storage fault over DATA, DONE, or cancellation, sends one bounded STOP while intake is active, and joins the pending notification task. A validated DONE instead owns its admitted writer barrier through cancellation; it sends no extra STOP and cannot report success, seal, or ADVANCE after cancellation or failed storage. Timeout or protocol failure followed by owner cancellation retains that cancellation after STOP and INTERRUPT cleanup when the writer is healthy. A newly constructed transfer error chains through the original Fatal object to its SQLite cause. The existing arena caps the selected batch at 512 MiB, the notification stream caps accepted payloads at 2 MiB, and writer progress is a high-water counter rather than an unbounded packet queue. The firmware can advance its cursor on BLE-confirmed transmission before host durability, so STOP and withholding host ADVANCE cannot promise lossless recovery after a force-stop or disk error.
